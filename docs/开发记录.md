# Vnav · 自建浏览器主页

**V1.0.0**

一个自托管的浏览器起始页。PHP + SQLite，单文件数据库，零外部依赖、零 CDN 请求。
登录后台后，复制任意网址在主页按 `Ctrl+V` 就能自动识别标题、生成简称、抓取站点图标并入库。

> **第一次部署请直接看 [`部署说明.md`](../部署说明.md)** —— 按步骤走，不用读完整份 README。
> README 是设计与实现记录，讲的是「为什么这么做」。

## 关于下面的版本号

**V1.0.0 是第一个对外发布的正式版，版本号从这里重新开始。**
下面这张表和后面各节里出现的 V1.2.x / V1.3.x / V1.4.x，都是 V1.0.0 之前的内部迭代编号——
一个版本里可能推倒重来过三四次，那些编号记录的是「改到第几稿」，不是对外发布过的版本。

保留它们是因为这些记录本身就是设计依据：每一行背后是一次被否掉的方案或者一个踩过的坑。
读的时候只需要关心「为什么改成这样」，不必在意那些编号。

## V1.3.0 改了什么

用户的原话是「三套皮肤实际上就是针对一套设计风格的换色，希望把主页的设计风格完全推倒重来」。
这一版重做的是四件具体的事：卡片怎么排、导航怎么走、三套皮肤各自长什么样、标题能不能完整读出来。

### 1. 卡片：先解决「看不清」

**标题不再被截断。** 旧版宫格用 `-webkit-line-clamp: 2` 硬截断，实测 15 个卡片标题里有 3 个读不全：
`Agentic Infrastructure` 变成 `Agentic / Infrastructur…`，`Rust Programming Language` 直接少了半个词。
读到的不是名字，是残句 —— 这比排版丑严重得多。

关键不在于加不加上限，而在于**解除截断必须动好几个属性**：

```css
/* ❌ 只写 white-space:normal 没用 —— line-clamp 是独立属性 */
.link-title { white-space: normal; overflow: visible; }

/* ✅ 必须显式 unset，并退出 flex 盒模型 */
html[data-layout='grid'] body.hp .link-title {
  display: block;
  -webkit-line-clamp: unset;
  line-clamp: unset;
  -webkit-box-orient: initial;
  white-space: normal;
  overflow: visible;
  text-overflow: clip;
  overflow-wrap: break-word;   /* 不是 anywhere */
  word-break: normal;
  min-height: calc(1.34em * 2); /* 一两行的标题条目也对齐 */
}
```

`overflow-wrap` 那行的取舍值得记：`anywhere` 会在任意字符断行，实测把「干杯~」的波浪号单独甩到了第三行；
`break-word` 只在整词实在放不下时才断，标点会跟随前字。

**格子宽度加了一档并封顶。** 旧版 `minmax(132px, 1fr)` 会被「被迫撑满」——
1087px 可用宽度 ÷ 132px = 8 列，每列被拉到 141.7px，而格子里只有一个 48px 图标加一行短字，左右全是空白。

```css
html[data-layout='grid'] body.hp .links {
  grid-template-columns: repeat(auto-fill, minmax(120px, 148px));
  justify-content: start;   /* 余量沉到右侧，不要摊给每一格 */
  gap: 8px;
}
```

实测：1440px 视口 7 列 × 148px（旧版 8 列 × 141.7px）；768px 4 列；375px 3 列。

**同一排卡片高度严格对齐。** 这里踩了个典型的坑：只给卡片写 `height: 100%` 完全无效，
因为它的父级 `<li>` 没有被撑开，百分比没有参照物。必须两步：

```css
body.hp .links > .link-item { display: flex; height: 100%; }
body.hp .link-item > .link   { flex: 1 1 auto; height: 100%; }
```

> 需要说明的是：修完之后不同**行**之间仍然会有高度差（约 20px），这是网格行高按行独立计算的正常结果，
> 同一排内已完全对齐（实测 `li h=146.7 / a h=146.7`）。我一度把它当缺陷追查，是误判。

**紧凑列表是唯一保留单行省略的形态。** 它的设计目标就是「一屏塞下几十条」，固定行高是它成立的前提，不是缺陷。

### 2. 导航：从「筛选器」改成「目录」

**顶部标签不再把其他分组藏起来。** 旧版点一个标签只显示那一组，其余 `hidden`。
用户加过的东西突然看不见，第一反应是「我的链接是不是丢了」。
收藏夹的心智模型是目录 —— 内容全在，我跳过去看。所以 `role="tab"` / `aria-selected` / `tabpanel` 整套 ARIA 都拆掉了，
换成 `data-gjump` + `aria-current`：它现在是一组锚点，不是一个控件。

两种导航形态（左侧竖排 / 顶部横排）**行为完全一致**：点一下平滑滚到该组，滚到哪组就高亮哪个。
换导航方式不该让「页面怎么滚」也变掉。实现上两套 DOM 共用同一段 `ui.js` 逻辑。

**窄屏不再丢失导航。** 旧版侧栏在 1179px 以下直接 `display:none`，设了侧栏的人在手机上等于没有分组导航。
现在退化成一条吸顶的横向分组条 —— 功能保住，形态让位：

```css
@media (max-width: 1139px) {
  body.hp .gnav--side {
    position: sticky; top: var(--hp-bar);
    width: auto; max-height: none;
  }
  body.hp .gnav--side .gnav-track { flex-direction: row; }
}
```

**当前分组不再整块实心强调色**，改成「淡底 + 强调色细边 + 左侧一条 3px 短竖条」。
侧栏有七八项时，全实心会变成一列色块墙。

### 3. 五套皮肤：从「换色」变成「换材质」

旧版几套皮肤共用同一套阴影、同一套毛玻璃，只换背景色和强调色 —— 观感是「换了个色号」。
这次把材质也抽成了令牌：

| 皮肤 | 方向 | 圆角 | 内高光 | 毛玻璃 | 页面纹理 |
|---|---|---|---|---|---|
| **纸白** | 印刷品 | 10px | `none` | `none` | 无 |
| **深夜** | 暗玻 | 15px | 内白高光 | `blur(18px) saturate(150%)` | 无 |
| **护眼** | 青瓷 | 12px | 白色内描边 | `none` | 45° 极淡纸纹 |
| **赛博** | 霓虹暗底 | 14px | 内霓虹高光 | `blur(14px) saturate(160%)` | 无 |
| **跟随系统** | 随系统 | 10px / 15px | 随系统 | 随系统 | 随系统 |

```css
/* 纸白：靠线条分界，不靠投影 —— 投影会让它变成「浮起来的网页」，不是纸 */
html[data-theme='paper'] {
  --hp-card-bg: #fdfbf6;
  --hp-card-blur: none;
  --hp-card-inset: none;
  --hp-r-card: 10px;
  --hp-page-tex: none;
  /* 宫格静止态托底：浅色皮肤留透明，图标自带浅底，再铺一层会糊成灰方块 */
  --hp-grid-bg: transparent;
  --hp-grid-line: transparent;
}

/* 深夜：卡片要有真实的层次 */
html[data-theme='night'], html[data-theme='auto'] {
  --hp-card-bg: rgba(255, 255, 255, .045);
  --hp-card-blur: blur(18px) saturate(150%);
  --hp-card-inset: inset 0 1px 0 rgba(255, 255, 255, .055);
  --hp-r-card: 15px;
}

/* 护眼：像水彩纸，不是发灰的绿屏 */
html[data-theme='celadon'] {
  --hp-page-tex: repeating-linear-gradient(45deg,
      rgba(90, 110, 70, .028) 0 1px, transparent 1px 5px);
  --hp-card-inset: inset 0 0 0 1px rgba(255, 255, 255, .5);
  --hp-r-card: 12px;
}
```

另外补了两处旧版的遗漏，都是「暗色皮肤下图标浮在纯黑上、没有边界感」的问题：

第一处是深夜，第二处是赛博 —— 赛博底 `#05060e` 比深夜更黑，问题更明显。
一开始是按皮肤名硬编码的，漏了赛博；现在改成令牌制，由每套皮肤自己声明托底：

```css
/* 各皮肤在材质块里声明 */
html[data-theme='night'] { --hp-grid-bg: rgba(255, 255, 255, .028);
                           --hp-grid-line: rgba(255, 255, 255, .05); }
html[data-theme='cyber'] { --hp-grid-bg: rgba(0, 240, 255, .035);
                           --hp-grid-line: rgba(0, 240, 255, .10); }
html[data-theme='paper'] { --hp-grid-bg: transparent;   /* 浅色不需要托底 */
                           --hp-grid-line: transparent; }

/* 宫格规则只引用令牌，不再认皮肤名 */
html[data-layout='grid'] body.hp .link {
  background: var(--hp-grid-bg);
  border-color: var(--hp-grid-line);
}
```

这样新增一套皮肤时，暗色就给自己一个托底、浅色留 `transparent`，不会因为忘了加选择器而漏掉。

> 选择器这里有个必须记住的写法：两个 `data` 属性挂在同一个 `<html>` 上，
> 写成 `html[data-theme='night'] html[data-layout='grid']`（html 套 html）永远匹配不到。

### 4. 一个记忆点：吸顶组签

这是这版唯一一个「不为功能、只为过目不忘」的设计。

分组标题在滚动时**贴住顶栏下沿**，像书架上的横档，任何时候都知道自己正看哪一组。
顶栏的标签指方向，吸顶的标题给确认，两份信息不重复。实测组签 `top = 63.9`、顶栏 `bottom = 63`，精确贴合。

组签的底色只铺文字所在的一小片，向右淡出：

```css
body.hp .group-head {
  position: sticky;
  top: calc(var(--hp-bar) - 1px);
  z-index: 20;
  background: radial-gradient(38% 120% at 4% 50%,
      color-mix(in srgb, var(--bg-0) 94%, transparent) 0%,
      color-mix(in srgb, var(--bg-0) 70%, transparent) 38%,
      transparent 72%);
}
```

第一版用的是整块 `linear-gradient` 铺 96% 不透明底色，在浅色皮肤下看不出来（与背景同色系），
在深夜皮肤上却变成一条肉眼可见的灰横带。改成 `radial-gradient` 并把半径从 60% 收到 38% 才干净。

> 顺带澄清一个我一度写错的注释：多个同级 `.group-head` 各自 `sticky` 到同一个 `top` **不会**互相堆叠 ——
> sticky 元素被约束在父容器内，一组滚出视口时它的标题跟着离开。实测两两重叠对数 = 0。

### 5. 五处一直在悄悄出错的地方

前面四节讲的是「设计成什么样」，这一节讲的是「原来哪里是坏的」。
这五处都不是设计阶段能想到的，全是把页面真的渲染出来、逐个读计算样式才露出来的。

**① `rgba(var(--x), .16)` 这个写法从来就没生效过。**

旧式 `rgba()` 只接受逗号分隔的**单通道值**，塞进 `240 180 41` 这种三通道会整条声明失效、回退成 `rgb(0, 0, 0)`。
隔离测试：

```css
rgba(var(--g), .22)   /* --g: 240 180 41  →  rgb(0, 0, 0)          ❌ */
rgb(var(--g) / .22)   /*                    →  rgba(240,180,41,0.22) ✅ */
```

全站 27 处（`home.css` 11 + `app.css` 16）已改成标准写法。
上一版导航激活项那个「莫名其妙的白框 / 黑框」就是它造成的 —— 我一开始怀疑是 `:focus-visible` 焦点环，
实测 `matches(:focus-visible) = false`、`outline = none`，假设被推翻，才顺着样式表遍历找到真因。

**② 默认圆角压在 `body.hp` 上，把五套皮肤的圆角差异全废了。**

这是最隐蔽的一处，因为它「看起来是对的」：

```css
body.hp { --hp-r-card: 12px; }                    /* 默认值 */
html[data-theme='paper'] { --hp-r-card: 10px; }   /* 皮肤想改成 10px */
```

自定义属性是**就近覆盖**的。`body` 是 `html` 的子元素，声明在 `body.hp` 上的值离目标元素更近，
于是 `html` 上那套 10 / 15 / 12px 全被这一个 12px 压掉。
结果是「三套皮肤圆角完全相同」，而代码里明明写着三套不同的值。

修法是把默认值上移到 `html`：

```css
html { --hp-r-card: 12px; }        /* 兜底 */
body.hp { /* 不再声明这个值 */ }
```

**③ 卡片形态还多设了一条下限，把差异又抹了一遍。**

```css
/* ❌ 想给卡片一个「不小于 13px」的下限 */
html[data-layout='card'] body.hp .link { border-radius: max(var(--hp-r-card), 13px); }

/* ✅ 圆角完全交给皮肤 */
html[data-layout='card'] body.hp .link { border-radius: var(--hp-r-card); }
```

`max()` 把纸白的 10px 和护眼的 12px 一起顶到了 13px。
修完 ②③ 两处，实测五套皮肤终于分别是 `10 / 15 / 12 / 14 / 10px`。

**④ 「赛博」皮肤下的主页卡片是坏的。**

重写材质时只给纸白、深夜、护眼三套写了 `--hp-card-*` 令牌，漏了赛博。
而这些令牌没有全局兜底值，于是赛博皮肤下卡片算出来是：

```
background: rgba(0, 0, 0, 0)        ← 透明
border: 刺眼的 currentColor 白框      ← 变量为空，回退
border-radius: 6px                  ← 初值
```

整块卡片等于不存在。已补全赛博的材质。

**⑤ 赛博的招牌质感被误伤。**

新版为了去掉一层发灰的雾，把 `.aurora` 与 `.grain` 一起 `display: none` 了。
但赛博的 **CRT 扫描线正画在 `.grain` 上** —— 一刀切让它只剩纯黑底，跟深夜皮肤几乎分不出来。

对照实验确认了取舍：

| 层 | 作用 | 结论 |
|---|---|---|
| `.aurora` | 大团光斑 | **保持关闭**。它确实会把 `#05060e` 抬成发灰的深灰，霓虹感全失 |
| `.grain` | CRT 扫描线（3.4% 不透明度） | **对赛博放行**。极淡横纹，不改变底色明度 |

```css
body.hp .aurora,
body.hp .grain { display: none; }
html[data-theme='cyber'] body.hp .grain { display: block; }   /* 只给赛博 */
```

顺带清掉一个从来没被引用过的令牌 `--hp-card-shadow`：它定义了 5 次、每次都是 `none`、全文引用 0 次。
留着会让人以为「静态阴影」是个可调项。

**另外还有一处断点冲突。** 旧版侧栏退化断点是 1179px，新版统一到 1139px。
中间那 40px 区间里新旧两套规则会互相覆盖、彼此打架。修法是把旧规则全部限定在主页之外：

```css
body:not(.hp) .gnav--side { ... }
```

### 6. 为什么新建 `home.css` 而不是改 `app.css`

`app.css` 被 `admin.php` 与 `login.php` 共用，直接在它身上重写主页视觉，后台和登录页会一起崩。

所以新建 `assets/home.css`（约 1300 行），把全部规则挂在 `body.hp` 之下：

- **特异性高一级** —— 不用 `!important` 就能覆盖旧规则；
- **作用域隔离** —— 后台与登录页压根不加载这个文件；
- **JS 选择器零改动** —— 类名一个没变，`ui.js` 里的 `$('.gnav-item')` 全都还在。

`app.css` 这版只做两件事，不改任何视觉：修正 16 处 `rgba(var())`；给旧的主页规则加上 `body:not(.hp)` 限定。

验证结果：登录页（`auth-body`，未引用 `home.css`）与后台**零影响**，两者视觉与功能均无变化。

## V1.2.2 改了什么

这一版解决的问题全是实际用出来的，不是设计阶段能想到的。

### 1. 游客态补回登录入口

V1.2.0 为了「日常浏览界面要干净」把顶栏收得只剩两个图标按钮，顺手把登录入口也收没了 ——
游客打开页面找不到任何进后台的路，只能自己敲 `admin.php`。

现在游客态右上角有一颗明确的「登录」按钮，登录后它自动换成编辑铅笔和管理后台齿轮。
窄屏只留图标（文字进 `sr-only` 靠 `aria-label` 达意），不挤顶栏。

### 2. 地址可以简写

`/admin`、`/login`、`/install` 三个不带 `.php` 的地址会自动 302 到对应页面。

之前输 `/admin` 会落到主页 —— PHP 内置服务器把 `/admin` 当成 `index.php` 的 `PATH_INFO`，
而 `index.php` 根本没看这个变量。修法是在 `index.php` 最前面识别 `PATH_INFO`，
命中白名单就跳转。**只认白名单，不做任意转发**，否则等于开了个开放重定向。

### 3. 编辑按钮的图标为什么消失

这是个典型的 CSS 继承坑，值得记一笔：

```css
.tbm-ico { color: var(--acc); }              /* 图标永远用强调色 */
.tbm-btn--edit[aria-pressed='true'] {
  background: var(--acc);                     /* 按钮底也变成强调色 */
  color: var(--acc-ink);                      /* 文字色换了，但没管图标 */
}
```

图标自己不继承按钮的 `color`，于是强调色的图标画在强调色的底上 —— 完全看不见。
用户以为按钮坏了，实际是「隐形」而不是「消失」。

两处修：给 `.tbm-btn--edit .tbm-ico` 强制 `color: inherit`；
同时把图标从单一铅笔改成「铅笔 ⇄ 叉」两枚按 `aria-pressed` 切换，
让「再点一下就是退出」这件事在视觉上直接说清楚。

### 4. 搜索引擎的品牌图标

原来引擎标志是「品牌色方块 + 一个首字」（B / G / 百 / D / 搜 / 3），22px 下认不出是谁。

改成内联 SVG 的形状标记：Bing 的折角 b、Google 的四段 G、百度的熊掌、DuckDuckGo 的鸭子侧脸、
搜狗的狗头、360 的环形箭头。**仍然不引外链** —— 站点的硬约束是零第三方请求，
外链 logo 一挂就破功；真 logo 又多是位图，22px 还得另存一套并处理版权。
形状标记在这么小的尺寸下已经够辨认，观感和真 logo 差别肉眼几乎看不出。

`.eng-logo-txt` 保留为兜底：万一 SVG 因任何原因没渲染，文字仍然顶上。

### 5. 默认引擎看得见了

之前点「设为默认」只有一条 toast，关掉就什么都不剩，下次打开也看不出哪个是默认。

现在三处状态同步：

- 下拉里当前默认引擎的名字下面多一行小字 **「站点默认引擎」**（强调色）；
- 已经是默认时，「设为默认」那颗按钮变成 **「当前已是默认引擎」** 并置灰，不再让你点一个什么都不发生的按钮；
- 手动切换引擎后，上面两项跟着重算。

这里有个容易写错的地方：**`cur`（现在用的，可能被 localStorage 覆盖过）和 `siteDefault`（站点设置里那个）是两件事**。
标记跟 `siteDefault` 走，勾选跟 `cur` 走。混用会出现「勾在 A 上、默认标在 B 上」的错位。

### 6. 后台侧栏名称补全

八个页签原来都是两个字（链接 / 分组 / 外观 / 统计 / 安全 / 升级 / 日志 / 说明），
抽象到不看内容猜不出是什么。全部补成四字：

**链接管理 / 分组管理 / 外观偏好 / 统计分析 / 安全控制 / 系统升级 / 更新日志 / 使用说明**

页内大标题同步改，否则侧栏写「链接管理」、页里写「链接」会显得割裂。
窄屏下侧栏变横向滚动条，四字名称撑到 380px 宽，靠 `overflow-x: auto` 滑动，不换行不截断。

### 7. 一键刷新名称、描述与图标

用户的原话是「很多图标和链接没有 logo，而且网站会自动变化」。
原有的「补抓缺失图标」只补空白的，既不管标题也不管描述 —— 那不够。

新增的刷新面板放在「链接管理」页顶部（它改的就是链接数据本身，和链接管理是同一件事的两个粒度）：

| 按钮 | 行为 |
|---|---|
| **全部刷新** | 覆盖已有标题/描述/图标，全部重抓 |
| **只补缺失的** | 只填空着的项，手工改过的名称和描述不动 |

实现要点：

- **分批走 cursor 协议**，每批 6 条。逐条要访问外站，一条能拖几百毫秒，一次跑完必被 PHP 超时掐断。
  用 `id > cursor` 跨批而不是 `OFFSET` —— 刷新过程中如果有链接被删，`OFFSET` 会错位跳条。
- **进度条不自动隐藏**，跑完留着显示「成功 N 条、失败 M 条」，一闪而过的 toast 会漏掉这些数字。
- **出错不清进度**：中断时保留已处理的计数，用户能看到「跑到第几条挂的」。
- 抓不到的（对方没提供、被墙、做了防盗链）跳过并计数，**不把原值清空**。
- 单条 URL 若是内网地址，SSRF 防护会直接拒绝并计入失败，不会去访问。

实测数据（本机 15 条链接）：缺图标从 10 条降到 6 条，图标缓存从 5 个增加到 9 个。
剩下 6 条是站点本身抓不到（Stack Overflow 返回 403 反爬、npmjs 与 hub.docker.com 本机网络不通、
GitHub 被本机 hosts 指向回环而正确拒绝），不是代码问题。

## V1.2.1 改了什么

这一版只做一件事：把「拖动卡片排序」做到底。
V1.2.0 已经能做前台编辑，但拖动排序有硬伤 —— 多列形态下往右拖不动，触摸屏上完全拖不起来。

### 1. 落点判定补上横向

之前只比纵向中位线，同一行里从上往下拖没问题，**从左往右拖完全没反应**。

```js
const inRow = y >= s.top && y <= s.bottom;
const before = inRow ? (x < s.midX) : (y < s.midY);
```

### 2. 不再插「占位虚线格」

这是根因，也是这一版最关键的一处返工。

上一版在网格里插一条 `<li class="drop-marker">` 示意落点。问题在于 —— **那条线自己也占一个网格单元**，一插进去后面所有卡片整体被推一格，「谁在谁左半边」的参照系在拖动过程中一直在漂。表现就是指示线永远黏在自己屁股后面。

改成**直接挪动被拖的卡片本身**，其他卡片用 FLIP 反向补偿做 180ms 让位动画：

```js
const flipAround = mutate => {
  const before = new Map([...list.children].map(k => [k, k.getBoundingClientRect()]));
  mutate();
  for (const k of kids) {
    const dx = before.get(k).left - k.getBoundingClientRect().left;
    if (Math.abs(dx) < 1) continue;
    k.animate([{ transform: `translate(${dx}px, 0)` }, { transform: 'none' }], 180);
  }
};
```

拖动全程用**起手那一刻的矩形快照**判定，不反复读 `getBoundingClientRect()` —— 边改边读等于自证，会抖。

### 3. 触摸端长按起拖

手指的位移和滚屏手势是同一套输入。不等浏览器判完就抢，会被 `pointercancel` 打断。

所以：按住 **260ms** 不动才起拖；期间手指滑动超过 **8px** 就放弃起拖、让用户正常滚页面。

两个只在真触摸上暴露的坑：

- **不能改 `touch-action`** —— 手势进行中改它，浏览器直接 `pointercancel`。要用 `passive:false` 的 `touchmove` 拦。
- **`selectItem()` 里的 `scrollIntoView` 会杀死拖动** —— 平滑滚动一启动，浏览器就把手势判给滚屏。拖动时必须传 `noScroll`。

### 4. 自动滚屏

拖到视口上下 88px 内自己滚，速度随深入程度线性加快（上限 22px/帧）。没有它，想把卡片挪出当前一屏基本不可能。

### 5. 主页面之外的几处

- 顶栏加铅笔按钮（`Ctrl`+`E`），登录后整页进编辑态，点卡片就地改，不再跳后台。
- 右下角加了个可关闭的小提示，告诉新用户 `Ctrl`+`V` 能直接加链接。编辑态下自动隐藏 —— 手机上它贴底，正好压住最下面两张卡。
- 后台新增「升级」「日志」「说明」三个页签。
- 拖动时被拖卡片的边框改虚线（它同时是「已选中」状态，两个实线描边叠在一起像多重边框）。

$sql = 'SELECT ... FROM links';

## 一、环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| PHP | **8.1+**（开发验证于 8.3.36） | 需要 `pdo_sqlite`、`curl`、`mbstring`、`gd` |
| Web 服务器 | Nginx 或 Apache | 也可用 PHP 内置服务器做本地试用 |
| 磁盘 | 约 20 MB（含地理库时约 55 MB） | 图标按站点缓存，每个 ≤128px、通常 1~10 KB；地理库另算 |
| 数据库 | **无需安装** | SQLite 由 PHP 内置，数据即 `data/home.db` 一个文件 |

### 必需扩展检查

```bash
php -m | grep -E 'pdo_sqlite|curl|mbstring|gd|fileinfo'
```

五个都要有输出。缺 `gd` 会导致图标无法降采样（功能仍可用，但图标体积会大很多）；
缺 `curl` 则自动识别标题/图标的功能失效，只能手工填。

### HTTPS 抓取的前提

自动识别要访问外部站点，PHP 必须有 CA 证书包，否则会报
`unable to get local issuer certificate (20)`。在 `php.ini` 里指定：

```ini
curl.cainfo = "/path/to/cacert.pem"
openssl.cafile = "/path/to/cacert.pem"
```

证书包可从 <https://curl.se/ca/cacert.pem> 获取。

## 二、安装

### 1. 上传并赋权

把整个 `vnav/` 目录传到站点根目录（或子目录，如 `/nav/`）。需要可写的只有两处：

```bash
chown -R www-data:www-data data/
chmod -R 775 data/
```

`data/` 下的 `home.db` 和 `icons/` 会在首次运行时自动创建，`icons/` 无需手动建。

### 2. 跑安装向导

浏览器打开：

```
https://你的域名/install.php
```

填写管理员账号与密码，它会：

- 建库、建表、写初始设置
- 生成 48 位随机 `secret`
- 用 `password_hash()`（bcrypt cost 11）写入密码哈希
- 生成 `inc/config.php`

**装完立刻删掉 `install.php`**，它是一次性脚本。

> 额外保险：安装器一旦检测到 `inc/config.php` 存在就会**硬锁定**——
> 表单消失、POST 直接拒绝，不会覆盖已有配置。
> 否则任何人重跑该页面都能重置管理员账号密码，这是致命漏洞。
> 确实要重装，手动删掉 `inc/config.php` 和 `data/home.db` 两个文件即可。

### 3. 生产环境务必确认

`inc/config.php` 里：

```php
'debug' => false,   // 必须 false，否则报错细节会暴露路径
```

并且在 Web 服务器上禁止直接访问 `inc/` 和 `data/`：

**Nginx**

```nginx
location ~ ^/(inc|data)/ { deny all; return 404; }
```

**Apache**（`.htaccess` 放在站点根）

```apache
RewriteRule ^(inc|data)/ - [F,L]
```

> `data/home.db` 若能被直接下载，等于数据库全裸。这一步不能省。

## 三、Nginx 完整示例

```nginx
server {
    listen 443 ssl http2;
    server_name nav.example.com;

    root /var/www/vnav;
    index index.php;

    ssl_certificate     /etc/letsencrypt/live/nav.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/nav.example.com/privkey.pem;

    # 输出压缩。PHP 自己会压 HTML（inc/compress.php），
    # 这一段主要管静态 CSS/JS —— 它们不经 PHP。
    # 已压过的响应 Nginx 会自动跳过，不会重复压。
    gzip on;
    gzip_vary on;
    gzip_comp_level 6;
    gzip_min_length 1024;
    gzip_types text/css application/javascript application/json image/svg+xml;

    # 有 Brotli 模块的话，比 gzip 再小 15~20%
    # brotli on;
    # brotli_comp_level 5;
    # brotli_types text/css application/javascript application/json image/svg+xml;

    # 静态资源长缓存：CSS/JS 带 ?v= 版本号，字体文件名固定
    location ~* \.(css|js|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }
    location ~* \.(png|jpg|jpeg|svg|ico|webp)$ {
        expires 14d;
        add_header Cache-Control "public";
    }

    location / {
        try_files $uri $uri/ =404;
    }

    location ~ \.php$ {
        include        fastcgi_params;
        fastcgi_pass   unix:/run/php/php8.3-fpm.sock;
        fastcgi_param  SCRIPT_FILENAME $document_root$fastcgi_script_name;
        # 导入完整地理库要一两分钟，30s 会超时
        fastcgi_read_timeout 300s;
    }

    # inc/ 整个挡掉（含 config.php）
    location ^~ /inc/ { deny all; return 404; }

    # data/ 挡掉，但必须放行 icons/ —— 站点图标就存在那
    location ^~ /data/icons/ { try_files $uri =404; expires 30d; }
    location ^~ /data/       { deny all; return 404; }

    # 兜底：不允许访问隐藏文件
    location ~ /\. { deny all; return 404; }
}
```

> **`data/icons/` 那条不能省。** 写成 `location ~ ^/(inc|data)/ { deny all; }`
> 会把图标一起拦掉，结果是所有站点图标变成首字母色块 —— 页面不报错，
> 但你会以为抓取功能坏了。这是 V1.0.0 说明里的坑，本版已修正。

### Apache 完整示例

```apache
<VirtualHost *:443>
    ServerName nav.example.com
    DocumentRoot /var/www/vnav

    <Directory /var/www/vnav>
        AllowOverride All
        Require all granted
        DirectoryIndex index.php
    </Directory>

    # 压缩。PHP 已压过的响应不会重复压。
    <IfModule mod_deflate.c>
        AddOutputFilterByType DEFLATE text/html text/css text/plain \
            application/javascript application/json image/svg+xml
        Header append Vary Accept-Encoding
    </IfModule>

    # Brotli（Apache 2.4.26+）
    <IfModule mod_brotli.c>
        AddOutputFilterByType BROTLI_COMPRESS text/html text/css text/plain \
            application/javascript application/json image/svg+xml
    </IfModule>

    # 静态资源缓存
    <IfModule mod_expires.c>
        ExpiresActive On
        ExpiresByType text/css              "access plus 1 year"
        ExpiresByType application/javascript "access plus 1 year"
        ExpiresByType font/woff2            "access plus 1 year"
        ExpiresByType image/png             "access plus 14 days"
        ExpiresByType image/svg+xml         "access plus 14 days"
    </IfModule>
</VirtualHost>
```

> 项目自带的 `.htaccess` 已经处理了压缩、缓存、`inc/` 与 `data/` 的拦截
> （包括 `icons/` 的放行），上面这些写不写都行。写在这里是为了让你看清
> 「服务器层面还能补什么」。

## 五、日常使用

### 登录

访问 `/login.php` 登录。登录后主页右上角出现「后台」入口，进入可管理链接、分组、外观、密码四个页签。

登录限流：同一 IP **15 分钟内失败 5 次即锁定 10 分钟**，无需额外配置。

### 快速添加（核心功能）

1. 登录状态下，复制任意网址到剪贴板（`https://github.com/xxx` 或裸域名都行）
2. 在主页按 **`Ctrl+V`**
3. 弹出面板里自动填好：网址、识别出的标题、基于标题生成的简称、站点图标
4. 确认或改一下分组，点保存

同一条 URL 重复添加会被拒绝，并保留你已填的内容不清空。

识别逻辑：

- 标题优先取 `<title>`，为空才退回 `og:site_name` → `application-name` → `og:title`
- 自动剥掉域名重复尾巴（`哔哩哔哩 - bilibili.com` → `哔哩哔哩`）和颜文字
- 图标抓不到时降级为「首字母色块」，色相由域名哈希决定，保证同一站点颜色稳定
- 图标统一降采样到 **128px** 再落盘（1024×1024 源图 11.6 KB → 3.9 KB）

### 四种展示形态

右上角「卡片聚合 ▾」里切换，选择记在浏览器里（localStorage），**同时**同步到数据库
作为新访客的默认值：

| 形态 | 版式 | 适用 |
|---|---|---|
| **卡片聚合** | 图标在上，名称 + 一句描述，自适应列数（240px 起） | 默认。信息量最全，适合每天扫一眼 |
| **横排菜单** | 单行胶囊串起来 | 入口少、想一行扫完时 |
| **紧凑列表** | 单列密集行，固定行高 | 入口多（30+），一屏看尽 |
| **图标宫格** | 大图标居中，格子 120–148px | 只要图标，最接近手机主屏 |

> **宫格的标题不再截断。** 旧版用 `-webkit-line-clamp: 2` 硬截断，
> `Rust Programming Language` 直接少了半个词 —— 读到的不是名字，是残句。
> 现在完整显示，英文长词也能在词内换行。
> 只有**紧凑列表**保留单行省略：它的设计目标就是「一屏塞下几十条」，固定行高是它成立的前提。

> 为什么两头都存：服务端默认值决定「别人第一次打开看到什么」，
> localStorage 决定「我自己切换后不要再被服务端默认值覆盖」。
> 首页 `<head>` 里有一段同步内联脚本抢在首帧前读 localStorage，
> 否则会出现「先按默认值渲染一帧，再跳成我的选择」的闪烁。

### 分组导航

链接分了几组之后，怎么在组间跳。后台 `外观 → 分组导航` 二选一：

| 方式 | 效果 | 适合 |
|---|---|---|
| **顶部标签** | 页面顶部横排标签，点击滚动到该组 | 分组少、每组内容多 |
| **左侧侧边栏** | 桌面左侧固定竖排，点击滚动到该组 | 宽屏、分组多、想一屏看全 |

**两种形态的行为完全一致**：点标签/条目就平滑滚到那一组，滚到哪一组就高亮哪一个。
换导航形态只该改变「导航条摆在哪」，不该连「页面怎么滚」都变掉。

> V1.3.0 之前不是这样：顶部标签是**真筛选**（点「工作」就把其他组 `hidden` 掉），
> 侧边栏才是滚动定位。同一份数据两种心智模型，用户加过的链接点一下标签就"消失"了。
> 收藏夹的心智模型是**目录** —— 内容全在，我跳过去看。现在统一按目录做。

实现上的几个决定：

- **只有一组时不显示导航** —— 一个标签孤零零挂着没有意义，还占掉一行高度
- **当前分组用「淡底 + 强调色细边 + 左侧 3px 短竖条」标记**，不用整块实心强调色。
  侧栏七八项时全实心会变成一列色块墙
- **窄屏不丢导航**：侧边栏在 `≤1139px` 退化成一条吸顶的横向分组条。
  这里踩过一次：最初写 `display:none`，用户设的侧栏在手机上凭空消失，功能等于被砍了
- **组签吸顶**：分组标题滚动时贴住顶栏下沿，任何时候都知道自己正看哪一组
- `<a href="#g0">` 而不是 `<button>`：没有 JS 时会退化成「跳到该分组」，功能降级但不断链
- 用 `data-gjump` + `aria-current` 而不是 `role="tab"` / `aria-selected` ——
  它现在是一组**锚点**，不是一个控件，配 tab 的 ARIA 反而会误导朗读器

### 主题与强调色

#### 五套皮肤

| 皮肤 | 底色 | 材质 | 适合 |
|---|---|---|---|
| **纸白** | 暖米 `#f2eee4`，不是纯白 | 细描边、无阴影、10px 小圆角 | 白天、光线充足时。纯白看久了刺眼，米黄压得住 |
| **深夜** | 墨紫 `#0e0c14` | 毛玻璃 + 内白高光、15px 大圆角 | 默认。暗光环境、晚上用 |
| **护眼** | 青瓷绿 `#e5ebdc` | 45° 极淡纸纹 + 白色内描边、12px 圆角 | 长时间盯着看。压低蓝光，但不是那种发灰的"护眼绿" |
| **赛博** | 近黑 `#05060e` + 霓虹青洋红 | 玻璃卡 + 霓虹细边、14px 圆角 | 想要视觉冲击。霓虹描边、扫描线、透视网格 |

不是「换了一个色号」—— 这是 V1.3.0 重写皮肤系统的核心。

全部**通过 WCAG 对比度校验**（正文 ≥4.5:1、UI 元素 ≥3:1）。这不是目测的，
是用真实渲染出来的颜色算的：

| 皮肤 | 正文/bg | 正文/卡片 | 强调色/bg |
|---|---|---|---|
| 纸白 | 14.42 ✓ | 16.11 ✓ | 3.72 ✓ |
| 深夜 | 17.14 ✓ | 15.89 ✓ | 11.43 ✓ |
| 护眼 | 11.19 ✓ | 12.81 ✓ | 3.52 ✓ |
| 赛博 | 18.34 ✓ | 17.54 ✓ | 11.78 ✓ |

> 浅色皮肤下强调色会自动压深（琥珀 `#f0b429` → `#96650f`），
> 否则黄色在米底上只有 1.48:1，按钮上的字根本看不清。

**赛博皮肤的特效**：卡片霓虹描边与内发光、顶部霓虹地平线光带、底部透视网格
（纯 CSS 渐变画的，零图片）、CRT 扫描线、9 秒一轮的扫描高光。

> V1.3.0 主页改版时为了去掉一层发灰的雾，把 `.aurora` 与 `.grain` 一起关掉了，
> 赛博的扫描线正画在 `.grain` 上，被误伤。现在 `.aurora` 仍关（大光斑确实会把近黑抬成深灰），
> `.grain` 对赛博单独放行。

所有动画都包在 `prefers-reduced-motion: no-preference` 里，关掉动效时静态效果仍在。

#### 强调色

五选一：琥珀 / 珊瑚 / 薄荷 / 天青 / 紫藤。

## 七、性能实测

本机实测（PHP 8.3 内置服务器，15 个链接，1440×900）：

| 指标 | 结果 | 目标 |
|---|---|---|
| TTFB | 7 ms | — |
| First Paint | 60 ms | — |
| FCP | **76 ms** | < 1800 ms |
| DOM Interactive | 22 ms | — |
| Load | 58 ms | < 2500 ms |
| **CLS** | **0** | < 0.1 |
| 首屏请求 | 10 个 / 189 KB | — |
| 外部请求 | **0** | — |

189 KB 里 71 KB 是两个自托管字体（`woff2`）、33 KB 是 CSS、22 KB 是两个 JS，剩下全是图标。
V1.1.0 的代码比 V1.0.0 多约 60 KB 源码，但**首屏传输反而小了** ——
因为新增的统计与访问控制全在后台（游客根本不下这些代码），
前台只多了一个引擎切换菜单。

| 文件 | 原始 | gzip 后 | 游客加载 |
|---|---|---|---|
| `app.css` | 57 KB | 17 KB | ✓ |
| `ui.js` | 12.5 KB | 5.0 KB | ✓ |
| `app.js` | 15.5 KB | 6.1 KB | ✗（仅登录后） |
| `admin.css` + `admin.js` | 51 KB | 13 KB | ✗（仅后台） |

优化手段：

- **单次查询**取全部链接，分组在 PHP 里做，避免 N+1
- 图标降采样到 128px 后落盘，并把原始 1024px 图直接丢弃
- `loading="lazy"` 已从首屏图标上移除——实测它反而导致首屏图标空白
- SQLite 开 WAL + `synchronous=NORMAL` + `busy_timeout`，读写不互斥
- 主题与形态在 `<head>` 内联脚本里应用，杜绝 FOUC 和由此产生的布局偏移
- 动画全部走 `transform`/`opacity`，并包在 `prefers-reduced-motion: no-preference` 里
- 字体、CSS、JS 全部同源，**没有任何第三方请求**（不碰 Google Fonts）
- 游客不加载 `app.js`（写操作那部分），比登录态少 15 KB
- **输出压缩在应用层**（`inc/compress.php`）：Brotli 优先、否则 gzip 6，
  小于 1 KB 的响应不压。不依赖 `mod_deflate`，Nginx/Caddy 上同样有效
- 静态资源长缓存 + `?v=N` 版本号，配合 `.htaccess` 的 `immutable`
- **归属地查询前先探库**：库没导入就直接返回「未知」，
  省掉每条访问三次无用的 `prepare + execute`
- **地理查询语句在请求内 prepare 一次**（`hp_geo_stmt()` 缓存），
  同一请求里 ACL 与统计各查一次时不再重复 prepare
- **设置读取走全局缓存**（`settings_all()`），但 `setting_set()` 会主动
  失效它 —— 保存后同请求内立刻按新值判定，不会用到上一套配置
- **统计不做按天聚合表**：万级行下 `COUNT/GROUP BY` 走索引是毫秒级，
  多一张表就多一处可能对不上的真相
- **过期明细自动清理**挂在打开统计页时（不用 cron），
  正好够当节拍器，且只在统计页才跑

## 八、安全设计

| 面 | 措施 |
|---|---|
| 密码 | bcrypt cost 11；登录成功即 `session_regenerate_id(true)` |
| 会话 | `httponly` + `samesite=Lax`，HTTPS 下自动加 `secure` |
| 写操作 | 全部要 `X-CSRF` 头，用 `hash_equals` 比对 |
| 限流 | 5 次失败 / 15 分钟窗口 / 锁 10 分钟，记录在 `login_attempts` 表 |
| **SSRF** | 抓取前拒绝回环、私有、保留 IP（`NO_PRIV_RANGE`+`NO_RES_RANGE`），拒绝 IP 字面量和无点主机名；不跟随跳转到内网；读取上限 512 KB |
| XSS | 所有输出过 `h()`（`htmlspecialchars` ENT_QUOTES）；JSON 输出统一 `json_encode` |
| SQL 注入 | 全量 PDO 预处理，无字符串拼接 |
| 上传 | 图标路径只接受 `data/icons/[A-Za-z0-9._-]+` 白名单，MIME + 魔数双重校验 |
| 隐私文件 | 见上文 Nginx/Apache 的 `inc|data` 拒绝规则 |

SSRF 那条值得单独说明：这是自建服务最容易被忽略的洞。如果不拦，
别人添加一条 `http://127.0.0.1:6379/` 就能让服务器去访问自己的内网服务。

## 十、常见问题

**Q：粘贴后识别不出标题，显示域名？**
服务器抓不到那个站点。检查：`curl` 扩展是否开启、CA 证书是否配置、目标站点是否屏蔽了非常规 UA。
不影响使用——手动改一下名称即可，图标同样会降级为色块。

**Q：图标显示成首字母块？**
三种可能：站点没提供 favicon、抓取时被反爬挡住、或 `data/icons/` 里对应文件被删了。
把 `data/icons/` 权限改成 775 后重新添加一次该链接。

**Q：能多用户吗？**
当前是单管理员设计，刻意不做多用户——个人主页不需要账号体系，
少一层就少一类漏洞。要多人用，建议各自部署一份。

**Q：能同步到多台设备吗？**
数据在服务器上，任何设备打开同一个地址看到的内容一致。
主题存在各设备本地（`localStorage`），这是有意为之——手机想用深色、桌面想用浅色，互不干扰。

**Q：换端口 / 换域名要改什么？**
不用改。所有跳转都是相对路径。
